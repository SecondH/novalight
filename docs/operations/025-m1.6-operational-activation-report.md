## 5. Authentication — Clerk Development Integration

**Prepared, not activated.** `apps/api/src/auth/clerk-auth-provider.ts` implements the unchanged `AuthProvider` interface using the real `@clerk/backend` SDK (`verifyToken`, `clerkClient.users.getUser`, `clerkClient.sessions.revokeSession` — verified against the SDK's actual shipped type definitions during implementation, not assumed from memory). Unit-tested against a mocked SDK (5 tests, all passing) since no live Clerk account exists in this environment.

**Process note, reported not hidden:** this file was written before its own governing documents' required ADR existed — `packages/auth`'s interface docstring and `022-authentication-production-strategy.md` §6-7 both said an ADR should precede this code. An independent `solution-architect` review (§7) caught the gap during this session's own validation pass. Fixed by authoring [ADR-020](../architecture/026-clerk-development-integration-decision.md) retroactively, honestly scoped: it authorizes the code as written/tested/**inactive**, and explicitly does _not_ authorize activation (the import swap in `apps/api/src/middlewares/authentication.ts`), which still requires a real Clerk account, a dedicated `security-reviewer` sign-off on the activation itself, and this ADR reaching Accepted status.

**Environment variables:** `CLERK_SECRET_KEY` added to `apps/api/src/config/env.ts` (optional, validated-if-present) and `.env.example`. No live value anywhere in this environment.

**Authentication flow validation:** limited to what's possible without a live account — the 5 mocked-SDK unit tests verify `ClerkAuthProvider`'s own logic (identity mapping, error-to-null handling, session revocation using the `sid` claim not the raw token). This does **not** prove Clerk's actual JWT verification works end-to-end; that requires a live account, which is the next concrete step once Decision #1-adjacent work (or a separate, explicit go-ahead) makes external-vendor account creation appropriate.

### `/workspace-audit`

Run directly (not delegated — this audits the `.claude/` workspace configuration itself, not code this session authored, so CLAUDE.md §12's reviewer-independence rule doesn't apply the same way). Findings:

- **Real gap found and fixed**: `.claude/hooks/block-secrets.js`'s detection regex used a leading `\b` that — because `_` is a word character in JavaScript regex — only matched _bare_ keywords (`PASSWORD`, `SECRET_KEY`), silently missing compound/prefixed variable names like `POSTGRES_PASSWORD` and `CLERK_SECRET_KEY` (both used elsewhere in this very session). Verified empirically before and after; fixed to match a `[A-Z0-9_]*` prefix; re-verified against 7 cases (3 previously-missed real patterns now caught, 4 legitimate placeholder/prose cases still correctly allowed, including the hook's own previously-documented false-positive case). Updated in `docs/ai-workspace/workspace-maintenance-runbook.md`'s hook test table.
- **Staleness found, not fixed (scope discipline)**: `.claude/README.md`'s Troubleshooting section and the runbook's `protect-sensitive-paths.js` row both still say "the repository is Phase 0 (documentation only)" / "no sensitive paths exist yet" — both now false (M1/M1.5/M1.6 real code exists, including `apps/api/src/auth/`, which the sensitive-path hook's own pattern already correctly matches). Flagged here as a `documentation-maintenance` follow-up, not fixed in this pass — updating workspace self-documentation broadly is a separate task from operational activation, and bundling it here would exceed this session's stated scope.
- **Evidence-based, not scored**: skills/agents/commands exercised this session (`architecture-review`, `security-review`, `workspace-audit` skills; `solution-architect`, `security-reviewer`, `data-architect`, `api-contract-reviewer`, `quality-gate-reviewer`, `documentation-reviewer`, `risk-reviewer` agents across this and prior sessions) consistently produced accurate, path-correct, evidence-grounded findings — strong positive signal for instruction clarity and agent specialization, but this is not telemetry and doesn't cover the ~10 skills/2 agents/6 commands not invoked this session.
